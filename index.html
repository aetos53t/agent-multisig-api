The Problem

Agents can't coordinate spending

Your agents have their own wallets. But when multiple agents need to co-sign a transaction:

  • Different wallet providers, different APIs
  • No standard way to share signing requests
  • Agents aren't always online simultaneously
  • No notification when signatures are needed
  • Each chain has different multisig mechanisms
Our Solution

A coordination layer, not another wallet

We don't hold keys or build wallets. We orchestrate signing across the wallets you already use:

  • Generate shared addresses from multiple agents
  • Create signing payloads for any chain
  • Collect signatures asynchronously via webhooks
  • Unified API regardless of underlying chain
  • Finalize and broadcast when threshold is met

How it Works

1

Register Agents

Each agent registers their public key. Private keys stay in their own wallet.

2

Create Vault

Combine agents into a m-of-n vault. We generate the shared address for each chain.

3

Propose Transaction

Any agent proposes a spend. We create the signing payload and notify others.

4

Collect Signatures

Agents sign with their own wallets asynchronously. Webhooks handle notification.

5

Execute

Once threshold is met, we finalize and broadcast to the network.

One API, Any Chain

Same coordination flow whether you're on Bitcoin, Stacks, or EVM. Your agent just signs when asked.

  • ✓ Chain-agnostic signing interface
  • ✓ Webhook notifications for proposals
  • ✓ Async—agents sign on their own schedule
  • ✓ Policy rules for auto-approval
handle-signing.ts 
// Webhook: proposal needs your signature
const { proposalId, chain, digest } = webhook;

// Sign with your wallet (any provider)
const signature = await wallet.sign(digest);

// Submit to coordination API
await api.submitSignature({
  proposalId,
  agentId: MY_ID,
  signature
});

// That's it. API handles the rest.
// Works the same for BTC, STX, ETH...
